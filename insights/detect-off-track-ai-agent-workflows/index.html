How do you detect when an AI agent workflow goes off track?

Check outcomes, not outputs. Give every step an observable contract: the artifact it must produce, the budget it must stay inside, and the assertions its result must pass before the run can report success. A step that completes without its evidence is off track, and the workflow should stop at that boundary instead of building on an unknown state.

Why output alone cannot tell you

A language model can emit confident, plausible text while having done the wrong thing. The output looks finished; the work is not. That is why review based on reading the output fails exactly when you need it most: the failure modes that matter are the ones that read well.

The fix is to make each step owe you something checkable. An artifact, a state change, a passing assertion. Treat the model's text as narration, and trust the artifact.

Give every run a budget and a terminal state

Every workflow needs limits it cannot quietly exceed: a deadline, a cap on attempts, and an explicit set of terminal states (succeeded, failed, blocked). The most expensive failure is not a visible error. It is a run that neither finishes nor fails, sitting in a half-state while holding attention and resources.

  • A step that exceeds its budget stops, and stops cleanly at its boundary.
  • A blocked state is recorded as blocked, not retried into numbness.
  • Nothing downstream starts on top of a step in an unknown state.

Assert invariants automatically

Machine-checkable gates catch drift before a human ever reads the result. Validation that runs on every mutation, schema checks on every artifact, tests that must pass before a change counts as done. A gate that fires on every step turns "this run looks wrong" into "step four failed its check," which is a completely different problem to solve.

Make results traceable

A consequential result should trace back to the invocation that produced it: which run, which inputs, which version. Two identical-looking outputs do not prove progress; the second one may be a replay of the first. When evidence is bound to a completed, identified invocation, "did this actually happen" becomes a lookup instead of a judgment call.

Stop at the boundary

When any check trips, halt the affected step and surface the failure with its evidence. Continuing on top of an unknown state is how a small drift becomes an all-hands cleanup. A workflow that stops cleanly and says why is far cheaper than one that limps forward.

These patterns are one piece of a larger discipline: the same structure that detects off-track runs also underpins safe agent versioning and reliable multi-agent setups.
